# Life Pilot 測試計畫、測試內容與檢查點

文件版本：2026-09-08

## 1. 測試目標

本文件用於功能驗收、回歸測試、上線前檢查與問題重現。最高風險項目為資料搬移、訂閱額度、RLS、行事曆分享、推薦活動匯入、日期時區及非同步頁面生命週期。

## 2. 測試環境矩陣

至少覆蓋：

| 類別 | 測試環境 |
|---|---|
| Web | Chrome 最新版、一般視窗與窄螢幕 |
| Android | 手機、平板、返回鍵與返回手勢 |
| iOS | iPhone、iPad、返回手勢、Deep Link |
| 桌面 | Windows；macOS 在可用裝置補測 |
| 帳號 | 免費一般使用者、Plus Cloud、Plus Local、管理者、即將到期、已到期 |
| 資料模式 | 全新帳號、既有雲端資料、既有本機資料、額度內、額度滿、超額 |
| 網路 | 正常、慢速、離線、API 逾時、Supabase 拒絕、來源網站失敗 |

每次提交前：


主要既有 Flutter 測試：

- 重複容忍批次寫入。
- 城市正規化、推薦活動去重及匯入日期驗證。
- HTTP timeout、retry、client close。
- 推薦活動更新按鈕政策。
- 題庫提示、分類、搜尋、可見性及新增後回填。

- 股票歷史資料及來源失敗狀態。

## 4. 身分驗證與帳號

### AUTH-01 註冊

- 步驟：以新 Email 註冊並完成驗證。
- 檢查點：法律同意紀錄建立；預設資料模式為雲端；未產生其他帳號資料。

### AUTH-02 密碼重設

- 步驟：發送重設信、點擊最新連結、設定新密碼。
- 檢查點：Deep Link 進入重設頁；舊連結／過期連結顯示可理解訊息；新密碼可登入。

### AUTH-03 跨分頁登出

- 步驟：同帳號開兩個分頁，在其中一頁登出。
- 檢查點：另一頁自動回登入頁；不再發送需驗證的 API 請求。

### AUTH-04 權限角色

- 一般使用者看不到股票、Business Plan 與管理工具。
- 管理者可以使用管理功能。
- 客戶端修改 metadata 不得取得管理者權限。

## 5. 雲端／本機與資料搬移

### STORAGE-01 首次登入

- 檢查點：登入前不顯示資料位置切換；登入後未設定者使用雲端；已設定者沿用上次選擇。

### STORAGE-02 雲端轉本機

- 準備：行事曆、記帳、積分、回憶、題庫、答題紀錄各有資料及圖片。
- 檢查點：全部寫入本機後才刪雲端；首頁、各清單、城市、帳戶總計皆正確；行事曆分享撤銷；設定頁自動關閉。

### STORAGE-03 本機轉雲端（額度內）

- 檢查點：完整上傳、來源本機資料刪除、IndexedDB 對應個人資料清空、切換至雲端、額度立即刷新。

### STORAGE-04 本機轉雲端（超額）

- 檢查點：整批失敗；雲端與本機均沒有部分變更；訊息指出資源、已使用、即將上傳、限額及剩餘額度。

### STORAGE-05 中途失敗

- 方法：模擬網路中斷或單一資料違反 NOT NULL。
- 檢查點：原資料保留；不切換資料位置；錯誤訊息包含失敗資源及後端原因；可修正後重試。

### STORAGE-06 Web 儲存生命週期

- 檢查點：Hot Reload 後 IndexedDB 資料仍在；清除網站資料後消失；UI 有本機資料只屬於此瀏覽器的警告。

## 6. 訂閱、額度與付款狀態

### SUB-01 免費額度邊界

- 分別建立至行事曆 30、記帳 30、積分 30、回憶 30、題目 50、分享 2 人。
- 檢查點：額度內最後一筆成功；下一筆失敗且訊息顯示正確數字；刪除一筆後可再新增。

### SUB-02 Plus 基準額度

- 檢查點：方案頁顯示版本、生效日、每季金額、到期日、各項 used/quota；圖片容量以 MB 顯示。

### SUB-03 倍率

- 將倍率設為 2。
- 檢查點：可倍增的資料筆數及圖片容量為版本基準的 2 倍；答題保留天數依設計不錯誤倍增。

### SUB-04 舊版未到期時加購新版

- 建立舊版 entitlement，再新增新版 entitlement。
- 檢查點：兩筆分開顯示；版本、生效日、付款、倍率、到期日各自正確；額度為兩者總和；新版不覆蓋舊版。

### SUB-05 個別到期

- 讓舊版先到期。
- 檢查點：只移除舊版額度；新版繼續有效；UI 不再顯示已到期權益；資料若超額進入正確限制流程。

### SUB-06 到期唯讀

- 檢查點：可查看、匯出及搬本機；不能新增／修改雲端資料；切至本機後可繼續新增。

### SUB-07 管理者設定

- 測試免費、替換 Plus、疊加 Plus、Cloud／Local、期限、備註及新價格版本。
- 檢查點：儲存成功後視窗自動關閉；免費版清空到期日；非管理者 RPC 回傳拒絕。

### SUB-08 免費帳號 inactivity

- 在 staging 建立超過 3 個月無資料活動的免費測試帳號。
- 檢查點：管理者不被刪除；活躍／付費帳號不被刪除；個人跨表資料與 auth 帳號一致清理；產生稽核紀錄。

## 7. 行事曆

### CAL-01 CRUD 與日期

- 新增全天、含時間、跨日、重複、只有開始日期的事件。
- 檢查點：月曆每週均顯示；切換月份不遺失；編輯日期後移至正確日期；通知時間正確。

### CAL-02 分享指定事件

- 只顯示目前月份畫面內、尚未到期事件，依近到遠排列。
- 先分享 8/31，再切 9 月追加分享 9/8。
- 檢查點：8/31 分享仍保留；對方同時看自己與他人事件；顏色區分；只能讀取不能修改。

### CAL-03 取消分享

- 檢查點：可取消單一事件、全部停止分享、受邀者停止查看；其他未取消事件仍可見。

### CAL-04 本機模式

- 檢查點：分享按鈕停用；從雲端搬本機時既有分享全部撤銷。

## 8. 記帳與積分

### RECORD-01 明細 CRUD

- 建立、編輯日期／數值／幣別／說明／一二級分類、刪除。
- 檢查點：今日小計與總計立即重算；列表依 date 排序；二級分類只在編輯時顯示；窄螢幕不溢位。

### RECORD-02 保留項

- 將既有含「餘」資料轉為保留項。
- 檢查點：SQL 不再依 `%餘%` 判斷；保留項永遠出現在查詢結果；一般資料仍受日期範圍限制。

### RECORD-03 載入更多

- 近 30 天有資料／無資料各測一次。
- 檢查點：無近期資料顯示最新一筆；載入更多不重複；後端確認沒有更多時按鈕立即消失，不需連點。

### RECORD-04 多帳戶首頁

- 檢查點：個人帳戶全部顯示；旅程記帳及團體積分只顯示最近 2 個；選擇後立即載入，不需手動重新整理。

## 9. 推薦活動、景點與回憶

### EVENT-01 篩選與地圖

- 關鍵字符合其他城市時自動切換城市。
- 點地圖城市名稱及數字。
- 檢查點：三個頁面均切回正確城市清單；Web 城市清單可捲動；手機不被捲軸遮住；無 overflow。

### EVENT-02 排序

- 活動：like／一般／dislike 各組內，未開始依 start date、已開始依 end date，再依時間、城市、地點、名稱。
- 景點：依城市、地點、名稱。
- 檢查點：Like／Dislike 只重排，不重新下載全部資料。

### EVENT-03 圖片、預覽與天氣

- 檢查點：無圖片不占空間；圖片縮圖解碼尺寸合理；只有 subEvents 才開 Preview；只載入可見且 8 天內的天氣；天氣標題不重複「雨」。

### EVENT-04 公開活動更新

- 正常來源：log 有 attempted/successful/failed/candidates，完成標記建立。
- 全部來源失敗：不建立今日完成標記，可再次更新。
- 全部重複：成功完成且 candidates=0。
- 兩名使用者同時更新：只有一人取得鎖，另一人顯示執行中。
- 刪除過活動：重新更新後不回來。
- 無時間資料：資料庫已有同名、同日、同城市、同地點事件時不重複匯入；不同上下午時間仍可並存。

### MEMORY-01 分批載入

- 檢查點：預設近 30 天；未來回憶可見；每次向前 30 天；資料去重；雲端／本機切換後不持續轉圈。

## 10. 遊戲與題庫

### GAME-01 題庫來源

- 一般使用者預設管理者題庫，不顯示管理按鈕；選我的題庫後才顯示新增／管理。
- 管理者的「我的題庫」等同管理者題庫。

### GAME-02 新增與編輯

- 分類選單、管理者自建分類、日／韓合法分類數字、完整句子 hint、重複檢查。
- 檢查點：Grammar 不要求使用者輸入底線或箭頭；Speaking 與 builder 共用來源時輸入規則一致；多行欄位及分類選單無 overflow。

### GAME-03 題目狀態

- 檢查點：停用題不會被抽取，也不會成為錯誤選項；啟用後恢復；已有答題紀錄刪除失敗時顯示人類可理解說明。

### GAME-04 遊戲流程

- 檢查點：連續按鈕不重複計分／存檔；返回鍵與手勢要求確認；Mario -20 分時仍可用上一頁離開；maxQuestions 練習不儲存正式進度。

### GAME-05 時間

- 檢查點：所有遊戲 created_at 顯示同一裝置時區；不可只有 Translation 正確、其他遊戲差 8 小時。

## 11. 股票（管理者）

- 背景最新資料更新中禁止選日期。
- 更新成功或失敗後可選歷史日期，但不可晚於資料庫最新日期。
- 選舊日期後不得被背景請求改回最新日期。
- Mac API 關機時可回退至 Supabase；不存在的 `stock_daily_price` 表應顯示可理解錯誤或使用實際表名。
- 載入失敗時提供重新選日期；抓最新按鈕不可誤標為所選日期重試。
- 批次寫入遇到 type＋date 或既定唯一鍵重複時忽略，不拋出整批失敗。

## 12. UI、效能與生命週期

- 手機、平板、寬螢幕檢查 Text overflow、bottom overflow、Dialog 無尺寸及可點擊區域。
- 搜尋文字只在按搜尋後生效；清除 X 可用；分類變更依產品規則立即套用。
- 長清單使用分批／Lazy build；圖片只在進入可見範圍時解碼。
- 離開頁面後完成的 HTTP、timer、stream、controller 工作不得呼叫已 dispose 物件。
- HttpClient 關閉後不再送出請求。
- Loading、empty、error、retry／重新選擇等狀態均有明確畫面。
- 多國語系在 zh/en/ja/ko 均無 untranslated message，日期與單位不硬編碼。

## 13. Supabase 安全驗收

- 所有 public table 啟用 RLS。
- 一般使用者只能讀寫自己的個人資料。
- 共享行事曆只能 SELECT 指定事件。
- 管理者資料與一般資料依政策正確隔離。
- `anon` 的 public table grants 及 RPC execute 均為 0（明確公開項目除外）。
- `SECURITY DEFINER` 函式固定空 search_path 並使用完整 schema。
- 股票表一般 authenticated 只有 SELECT，寫入由 service role 執行。
- 測試 orphan favorites、缺 owner_id、無效 country、重複唯一鍵及過期清理均為 0。
